# Afterstreet map generator guide

Reference for the **map chat** in this Project. Read it first, follow it, and update it when a decision changes. Started 19 October 2026, at game version 0.49.4. The main development chat's wish list is `docs/MAP_REQUESTS.md`. The companion app built on this engine is scoped in `docs/MAPS_BUILDER.md`.

## The role

**This chat learns how real places are turned into game worlds and builds Afterstreet's map generator**: the tools that take OpenStreetMap and other open data and turn it into the map squares the game loads. The goal is to recreate real places as accurately as the data allows.

- This chat owns the map tools (`tools/build_region.py`, `tools/fetch_road_names.py` and any new `tools/map_*.py`), the map file format, and this page.
- It does not change the game's code (`play.html`, `sw.js`). When the game needs to read something new (a new layer, a new tag), this chat writes a hand-off note for the main development chat, the same way the design chat hands over art.
- Generated output (`assets/springfield/*.js`, `assets/map.js`) is rebuilt by the tools, never edited by hand.

## Where the pipeline stands (checked 19 October 2026)

`tools/build_region.py` reads the Afterstreet map pack (`design/afterstreet_handoff/map_data/springfield_50mi`, not in the repo; it has to be attached to rebuild) and writes 711 squares of 0.05° (about 5.6 km) plus a 500 m margin, 79 MB in all.

| Layer | Source today | Detail | What is lost |
| --- | --- | --- | --- |
| Buildings | Map pack (OSM-derived), 4 density zones | Footprint, pack type, floors, name, shop/amenity, address | Real `height`, `roof:shape`, `building:part`, material, colour, courtyards (inner rings are dropped, here and in `fromOverpass`) |
| Roads | Map pack road classes | Centre line rounded to about 1 m, class only | Lanes, width, sidewalks, surface, one-way, bridges and layer; **tunnels are skipped** and bridges sit on the ground |
| Street names | Overpass, separate run | Voted onto roads by nearby points | Works, but is a patch for the pack lacking names |
| Water | Map pack | River and stream lines, lake polygons | River width, banks |
| Elevation | Terrarium tiles | 14.6 m in the 15 km core (stored every 20 m), 157 m outside (every 125 m) | Kerbs, ditches, embankments, cuttings, building pads, creek banks |
| Land cover | Map pack terrain classes | 78.6 m cells | Actual woods edges and real tree positions |
| Gaps | Generated by rule | 10,000 homes and shops in 20 missed boxes, 29,000 farmsteads | Marked `generated=yes` so real data can replace them |

The game's own map maker (`play.html`, `KEEP` list) keeps only 21 tags, so live downloads lose the same detail.

## What others do

| Project | How it turns real data into a world | Lesson for Afterstreet |
| --- | --- | --- |
| **Arnis** (OSM to Minecraft, Luanti) | Fetches OSM, elevation and optionally Overture for a box, then builds blocks; modes for terrain only, flat, or both; optional interiors | Keep fetching, processing and generating as separate stages; let Overture fill buildings OSM lacks |
| **Terra++ / Build the Earth** (Minecraft at 1:1) | Public elevation datasets, OSM roads and buildings streamed as tiles, trees from a global tree-cover dataset | Tree cover can come from data, not only from rules |
| **OSM2World** | Turns OSM into 3D models. Its 2026 terrain plan says plain DEM interpolation looks implausible: OSM knowledge (flat roads and water, inclines, bridges, tunnels, steps, cliffs, retaining walls) must reshape the terrain, without seams between tiles | Terrain must be *conformed* to the map, not just sampled |
| **Streets GL** | OSM vector tiles, buildings from the Simple 3D Buildings tags, terrain with levels of detail | Simple 3D Buildings is the standard to read |
| **osm2streets** (A/B Street) | Roads become thick lines with a left-to-right list of lanes (type, direction, width); intersections become polygons; short roads, dog-legs and dual carriageways are merged | Roads need real widths and junction polygons; use osm2streets directly or copy its rules (Rust with JS and Python bindings, Apache-2.0) |
| **Blosm / bpypolyskel** | Hipped roofs from the straight skeleton of the footprint; succeeded on 99.99% of OSM's 320,000 hipped roofs | Straight skeleton for roofs, with gables and skillions done by simpler rules |
| **Arma 3 Terrain Processor** | GIS shapes in, objects out: area fills (forests by density per hectare), line placers (hedges), point placers, masks that clear objects near roads, and a road module that levels terrain under roads | The same three placer kinds plus masks, driven by per-shape density |
| **Flight Simulator autogen** | OSM plus AI footprints from aerial imagery; players report ignored `height` and `building:part` tags and farm sheds turned into towers | Respect explicit tags, and sanity-check inferred heights by type |
| **Project Zomboid** | Knox Country is hand-built, loosely on Muldraugh, West Point and Louisville, with fictional towns mixed in | A recognisable place matters more than survey precision; our advantage is doing it by code at full scale |
| **7 Days to Die** | Random worlds from cells, town hubs and prefab rules by biome and slot | Building interiors as rule-driven slots, which Afterstreet already does |

## Data sources for Springfield, from most to least accurate

| Source | Gives | Resolution | Licence | Notes |
| --- | --- | --- | --- | --- |
| USGS 3DEP lidar (2020 FEMA/NRCS Missouri project) | Point cloud: ground, buildings, vegetation | Points every 0.5-1 m | Public domain, no restrictions | City of Springfield made its 1 ft contours for Greene County from this flight |
| USGS 3DEP 1 m DEM (seamless S1M, from mid-2025) | Bare-earth ground | 1 m | Public domain | Cloud-optimised GeoTIFF in 10 km tiles; 10 m DEM (1/3 arc-second) everywhere as fallback |
| OpenStreetMap | Roads, footprints, names, addresses, shops, water, barriers, lamps, trees | Survey-level where mapped | ODbL | Primary source; must stay attributed |
| Overture Maps buildings | OSM plus Microsoft, Google and Esri footprints, merged, OSM first | Varies; ML footprints less precise | ODbL | Fills buildings OSM misses; release 2026-09-23.1 |
| Mapterhorn | Merged global terrain tiles (terrarium, PMTiles; extract a box with `pmtiles extract`) | Varies by country | See project | Easy offline terrain where lidar is missing |
| NAIP aerial photos (USDA) | Colour of roofs and ground, checking work | About 0.6 m | Public domain | For checking and tinting, not for shipping imagery |

The lidar is the biggest accuracy gain available: subtracting the ground from the first-return surface gives **every building's real height and roof shape** and **every tree's position and height**, which OSM rarely has. Height inference without it is the fallback (a random-forest study on footprints and attributes got 0.8 m mean error).

Note: the cloud workspace cannot reach Overpass or most data sites (only package registries). Downloads go through the user, or through a tool the user runs, then get attached here.

## The engine, stage by stage

Each stage writes its own intermediate file, so a stage can be redone without the rest (the Arnis split).

### 1. Fetch
A box of OSM (Overpass or a Geofabrik extract), Overture buildings for the same box, the 1 m DEM tiles, and optionally lidar tiles. Everything cached on the drive.

### 2. Conflate
- OSM wins. An Overture or lidar building is added only where no OSM footprint overlaps it by more than 30%.
- The existing `generated=yes` fill stays only where neither source has anything.
- Every feature keeps a `src` tag (`osm`, `ovt`, `lidar`, `gen`) so the game and future rebuilds can tell real from made-up.

### 3. Normalise tags and fill defaults
One table per feature type turns raw tags into the numbers the game needs, with the source of each default noted. Examples:
- Roads: lanes and width from tags, else by class (general US practice: lanes about 3.0-3.6 m, a two-lane residential street about 9-10 m kerb to kerb, plus parking where tagged).
- Buildings: height from `height`, else lidar, else `building:levels` × the storey height by type (3.0 m homes, 3.5 m shops and offices, 4.5 m industrial, from the design doc), else inferred by type and area.
- Roofs: `roof:shape`, else lidar, else by type (homes gabled or hipped, shops and big buildings flat).

### 4. Terrain, conformed to the map
Start from the 1 m DEM (resampled to a 2 m game grid in the core, coarser outside), then reshape it with what the map knows, in this order:
1. **Water** levels flat across each lake and pond; rivers step down along their line; banks cut to a sharp edge (the art guide wants sharp drops at creek banks).
2. **Roads** flattened across their width and smoothed along their length to a maximum grade by class; cuttings and embankments where the road leaves the ground, blended to the natural slope a few metres out.
3. **Kerbs**: road surface 15 cm below the sidewalk, as a sharp step (the art guide's sharp kerbs).
4. **Bridges and tunnels** from `bridge`, `tunnel` and `layer`: a bridge deck is a structure over untouched ground; a tunnel leaves the terrain alone.
5. **Building pads**: the ground inside each footprint set to one level (the floor), with the outside lowered or a plinth exposed on slopes.
6. **Seams**: every edit is done on the global grid before cutting into squares, so neighbours always agree.

### 5. Streets
Thick roads with lane lists and polygon junctions (osm2streets rules), sidewalks from `sidewalk` tags or by class in town, crossings and traffic signals from OSM nodes, driveways (`service=driveway`) to the garages they serve.

### 6. Buildings
- Read **Simple 3D Buildings**: `height`, `min_height`, `building:levels`, `roof:*`, `building:part` (parts replace the outline in 3D), material and colour.
- Keep **inner rings** (courtyards, light wells).
- **Square up footprints**: corners within a few degrees of 90° are made exact, and each building gets its own grid along its longest wall, so the 0.25 m wall cells and 0.5 m studs line up with the walls instead of with north.
- Roofs from the straight skeleton (hips), with gables, skillions and flats by rule; lidar decides the shape where present.
- Entrances from `entrance` nodes, so the front door is where the real one is.

### 7. Land cover and trees
- Woods edges from OSM `landuse` and `natural`, refined by the lidar canopy.
- **Real trees**: one tree per lidar canopy peak, with its real height, in place of rule-planted street and yard trees where data exists; the 0.33 rules stay as the fallback.

### 8. Street furniture from OSM points
Street lamps, hydrants, benches, bins, bus stops, traffic signals, stop signs, power lines and poles, fences, walls, hedges and gates (`barrier`). Each maps to a design-chat prop, and only what is mapped is placed; rules fill the rest, flagged `gen`.

### 9. Pack for the game
- One file per square as today, with layers the game can skip (terrain, streets, buildings, cover, props).
- Coordinates as whole centimetres from the square's corner, delta-encoded, instead of 6-decimal degrees; elevation as 10 cm steps delta-encoded. Expected to cut the 79 MB well below half (to be measured).
- Attribution in every file (`© OpenStreetMap contributors (ODbL)`, plus each other source used).

## How accuracy is checked
- A list of known places (the square, the courthouse, Missouri State, a river bridge, a hill street) checked against aerial photos after each rebuild.
- Numbers per square: buildings by source, buildings with a real height, roads with real widths, terrain error against the lidar ground at sample points.
- A preview page in `art-tests/` that draws one square from the generated file, so a rebuild can be looked at before it reaches the game.

## What the main chat has asked for

`docs/MAP_REQUESTS.md` (written at 0.49.5) is the main development chat's list. In short, most useful first:

1. **Needed first:** road `name`, `ref`, `alt_name`; building `height`, `min_height`, `building:levels`, `roof:shape`, `roof:levels`, with a flag for mapped or guessed; building use (`building`, `amenity`, `shop`, `office`, `tourism`, `healthcare`, `man_made`, `name`); full addresses, plus address points for buildings without one.
2. **Roads:** `lanes`, `oneway`, `maxspeed`, `surface`, `bridge`, `tunnel`, `layer`, `junction`, `sidewalk`, `parking:lane`, `lit`; junction nodes (signals, stop and give-way signs, crossings, bollards, barriers, gates); street furniture points.
3. **Power (for 0.59):** plants with `plant:source`, generators, substations, lines, minor lines, poles, towers, transformers, solar farms; water towers, treatment works, pumping stations, fuel stations and depots.
4. **Land and ground:** land use and cover classes, parks and pitches, water with widths, dams and weirs, bridges with deck height, railways with crossings and stations, cliffs, quarries, embankments, elevation in the same tile layout.
5. **More places:** a pack builder that takes a box and a size and writes the same file names; first a small town, a bigger city and a rural county, each under 100 MB.
6. **Hand-over:** one zip with the pack, a `REFERENCE.md` of every property, feature counts per file, and the OSM extract date. The game reads it in 0.49.6 (street names, address search), then 0.56 to 0.60.

The requests ask to keep the pack's GeoJSON layout, so the first deliverable is a **new map pack in the same layout with the extra properties**, built from an OpenStreetMap extract instead of the old pack. The conformed terrain, street geometry and lidar work below come after, as new layers beside it.
